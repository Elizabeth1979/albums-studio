# Phase 4 — captions, story notes, and alt text

Owners can now write three separate kinds of text about a photograph, choose who each one
is for, and see at a glance which pictures still have nothing said about them.

## What shipped

Selecting a photograph opens an editor beneath the gallery holding:

- **Caption** — a short label, with an explicit choice between keeping it private and
  showing it under the photo in a shared album.
- **Alt text** — the description a screen reader reads out. Always delivered to whoever
  needs it, whatever was chosen for the caption, because it is not the same kind of secret.
- **Story notes** — longer memories. A photo can carry several; each has its own
  visibility, can be edited in place, and needs a confirmation before it is deleted.

Photo tiles are now buttons rather than decorative images. The button carries the
description — alt text when the owner has written some, position otherwise — so a gallery
reads as a list of pictures instead of a row of identical controls, and the image itself
stays out of the accessibility tree so nothing is announced twice.

## Hidden text had to be made hidden first

`albums.cover_photo_id` aside, this is the first feature where the database holds text the
owner has decided not to publish. Two paths would have served it anyway:

- `public.get_shared_album` returned every caption to anyone holding a share token.
- `anon` held `grant select on table public.photos`, so a caption would be readable
  directly through the Data API on any album whose visibility became `public`.

Both are closed. The function returns a caption only when it is marked visible, and `anon`
now holds a named column list that excludes `caption`, `owner_id`, and the internal
measurement columns.

The revoke that fixed the second one did not work on the first attempt, and the failure was
silent: `revoke select (caption) ... from anon` against a table-level grant parses, succeeds,
and changes nothing. Reading `information_schema.column_privileges` afterwards is what
caught it.

The same check caught that `create table public.photo_stories` had handed `anon` full
select, insert, update and delete, because Supabase's default privileges grant everything on
new `public` tables. RLS was refusing anon either way, but this project deliberately keeps
grants and policies as two independent layers and one of them was open.

Both findings are now rules in `AGENTS.md`.

## Verified against the real database

A rolled-back probe run as the actual `authenticated` and `anon` roles confirmed:

- the owner can insert a story and read it back in the same statement — the `RETURNING`
  trap that broke Phase 3 does not apply here
- the owner can write captions, visibility, and alt text
- `anon` is refused story notes entirely, and refused captions
- `anon` can still read alt text, which is the point of alt text
- a hidden caption comes back as null through a share token; a visible one comes through

## Known gaps

- Story notes have no `region`, `audio_path`, or `transcript`. Those belong with Phase 5
  voice capture rather than being added speculatively now.
- Shared viewers still cannot see any of this: there is no sharing UI, and story notes have
  no anon path at all by design. Phase 6 adds shared delivery through trusted server code,
  which is where visible stories become readable.
- Nothing searches this text yet. The roadmap frames written context as a flywheel that pays
  the owner back in better search; that payoff arrives with Phase 5 and Phase 7.
