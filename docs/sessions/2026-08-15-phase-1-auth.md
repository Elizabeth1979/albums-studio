# Phase 1 authentication

**Keywords:** React, TypeScript, Vite, Supabase Auth, magic link, protected library,
accessibility, tests.

Albums Studio now has its first application checkpoint: a React and TypeScript frontend,
email/password signup and sign-in, passwordless magic-link sign-in, secure identity refresh
through Supabase claims, sign-out, and a protected empty library. Signup sends `display_name`
metadata so the existing database trigger creates the matching profile row.

Dependencies are pinned and limited to the current phase. The browser receives only the
Supabase URL and publishable key through git-ignored local environment configuration. Strict
type checking, component tests, a production build, `npm audit`, and a local HTTP smoke test
all pass.

The application is linked to its GitHub repository in Vercel and deployed at
[albums-studio.vercel.app](https://albums-studio.vercel.app). Production and Preview builds
receive only the browser-safe Supabase URL and publishable key. Node 24 is pinned for
repeatable Vercel builds.

Email confirmation is disabled for lower-friction signup. Passwords have no application-side
composition or length rule; Supabase still enforces its platform minimum of six characters.
Magic links only sign in existing accounts and never create an account implicitly.

Before Phase 2 begins, complete the human checkpoint and verify signup, password or
magic-link sign-in, sign-out, the protected library, and the resulting `profiles` row.
